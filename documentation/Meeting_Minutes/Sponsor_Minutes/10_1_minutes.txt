Q: In terms of response time, do we have a minimum time for detection
A: it will depend on the anomoly, some will present quick and some may be slow
Will depend on how often we are getting data from the sensors as well
Once we know sampling rates, then we will know more about the data input
Each sensor will have a different sampling rate, but must know how the data is getting parsed into packets
There will be some manuvering to figure out the best way to handle incoming data
This is another reason communication with the other teams will be very important
There will be an online database we can pull from
Realtime warnings/errors: balance between complexity & accuracy vs response time and efficiency
We can have a faster model run real time and a more in depth one that doesn't run in real time for larger analysis
We probably don't need a frontier model with APIs, we can run a local model

Q: What are we using the data to detect?
A: Air quality: if we begin to see deviations from air quality from the nominal data, the digital twin should be able to see the differences much sooner than the astronaut
In theory the model should see deviations in the data given before critical problems develop
Likewise, having a digital twin trained on lots of data allows for simulations to be ran to see where things can break

Q: Previously, there were a lot of analog astronaut runs, so is the data all gathered by sensors, or will we also incorporate previous data?
